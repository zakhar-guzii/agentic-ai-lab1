# Chornohora trail dataset

Card for `data/chornohora.json`, the graph of marked hiking trails for the `trails` server. Generated by `scripts/build_dataset.py`; do not edit by hand, rebuild instead.

- Build date: 2026-11-19; `dataset_version`: `2026-11-19-545411ea`
- Trails and points: © OpenStreetMap contributors, via the Overpass API; licence ODbL 1.0, the dataset is a derivative database under the same terms
- Elevations: OpenTopoData `srtm30m` (SRTM, ~30 m), segment profile sampled every 100 m
- Region (south, west, north, east): `47.95, 24.27, 48.32, 24.8`

## How it was built

The script merges three sources into one graph: trails from OSM, points of interest from OSM, and elevations from a DEM. Steps, in order:

1. **Trails (Overpass query 1).** All `route=hiking` relations in the region, their lines and the line vertices. Lines are clipped to the region. Only marked routes are used: hikers follow the marking, and unmarked `highway=path|track` would add noise. This build uses 670 OSM lines.
2. **Points of interest (Overpass query 2).** Named peaks (`natural=peak`), possible shelters (`tourism=alpine_hut|wilderness_hut|camp_site|chalet|guest_house|hotel`, `amenity=shelter`) and settlements (`place=village|hamlet|town`).
3. **Attaching points to trails.** Each point is compared with its nearest trail vertex: closer than 1 m, the point becomes that vertex (8 merges); up to 50 m, it becomes its own node joined by a straight synthetic edge (242 edges); farther, it is dropped (333 points).
4. **Manual decisions.** Only the 14 objects in `VERIFIED_HUTS` become `hut`: the same tags mark picnic shelters and hotels that do not take hikers (439 candidates dropped). The reasons come from the objects' OSM tags and descriptions and were not checked on site. `MANUAL_LINKS` joins important points lying farther than the threshold:

   - `w144275342` → vertex `n285889626`: Zarosliak: centre of the base polygon is ~160 m from the trails; marked routes to Hoverla start at the base, this vertex is where they start in the main network
   - `w144275342` → vertex `n4936465741`: Zarosliak: nearest vertex of the routes to Lake Nesamovyte, which also start at the base; in OSM this network is not connected to the Hoverla routes (a ~30 m gap on the base grounds)
   - `n337604448` → vertex `n12110363555`: Lazeshchyna: village centre is 69 m from the marked route through the village; starting village for Hoverla climbs

5. **Segments.** Lines are cut at every node: junctions, line ends and attached points. A segment's `km` is the length of its geometry. Connected components are kept, none is dropped.
6. **Elevations.** Each segment is sampled every 100 m; OpenTopoData `srtm30m` gives the elevation of every sample. The profile gives `ascent_m`, `descent_m` and `max_ele_m`; `above_treeline` means `max_ele_m ≥ 1500`, `exposed_ridge` means `max_ele_m ≥ 1700`.
7. **Forecast city.** Each node gets the nearest city of the table below, in a straight line; the weather check uses that city's forecast and corrects temperature for the elevation difference.

| Forecast city | Elevation, m | Nodes | Farthest node, km |
|---|---|---|---|
| Yasinia,UA | 651 | 174 | 13.3 |
| Vorokhta,UA | 746 | 216 | 17.7 |
| Verkhovyna,UA | 599 | 218 | 22.8 |
| Rakhiv,UA | 440 | 61 | 14.2 |
| Hoverla,UA | 671 | 490 | 20.6 |

City names: each name gives `ok` in `carpathian-weather-probe`, and OWM `/data/2.5/forecast?q=<name>` resolves it to the same town within 10 km of the table coordinates: Yasinia 0.04 km, Vorokhta 0.91 km, Verkhovyna 2.74 km, Rakhiv 0.50 km (checked 2026-11-18); Hoverla < 0.01 km (checked 2026-11-19).

## Limitations

- Only marked OSM routes: the graph is as complete as OSM. A trail missing there is missing here.
- The graph has 24 disconnected parts; no route is built between parts.
- `exposed_ridge` is an elevation threshold, not a terrain analysis.
- Huts are taken from OSM descriptions and not checked on site.
- SRTM (~30 m) smooths sharp ridges and peaks; elevations may differ from the map by tens of metres.

## How to rebuild

```
uv run python scripts/build_dataset.py --plan-only   # statistics, hut candidates, discarded points; writes nothing
uv run python scripts/build_dataset.py               # full build: overwrites both files
```

Queries, manual decisions and source quotas are in the script; how the graph is built and its limits: `docs/contracts.md`, 1.1, and `docs/design.md`, 4.
